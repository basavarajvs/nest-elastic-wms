# Document 5: Outbound - Picking after wave allocation

=== Start ===
verify if this is correct
In Manhattan WMS, once a wave is released and inventory is allocated, the **picker** takes over.

The picker's job is to:

* Get next task from system
* Travel to pick faces
* Scan location check-digits
* Pick items and confirm quantities
* Scan items into destination totes/pallets
* Handle short picks

---

# Before Picker Starts

System already has:

```text
Sales Order
   ↓
Wave Released
   ↓
Inventory Allocated
   ↓
Pick Tasks Generated
```

Order status may be something like:

```text
Allocated
```

or

```text
Ready for Pick
```

---

# What Picker Sees

RF Menu:

```text
Outbound
   → Picking
   → Get Work
```

---

# Step 1: Get Task & Scan Cart

Operator presses:

```text
Get Work
```

System assigns:

```text
Pick Task
Locn: P-05-A-01
```

Operator scans their empty tote:

```text
TOTE-999
```

---

# Step 2: Travel & Scan Check-Digit

Operator drives to location.

RF asks:

```text
Scan Location Check-Digit
```

Operator scans:

```text
CHK-8839
```

System validates they are at the exact correct bin.

---

# Step 3: Scan Item & Enter Qty

RF asks:

```text
Scan Item
```

Operator scans:

```text
ITEM1001
```

RF:

```text
Pick Qty = 5

Enter Picked Qty
```

Operator enters:

```text
5
```

---

# What Manhattan Validates

System checks:

* Correct check-digit for location
* Correct SKU scanned
* Quantity picked <= Quantity allocated
* Destination Tote is valid for this order/wave

If wrong item scanned:

```text

Item not expected at this location
```

# Document 6: Outbound - Packing

=== Start ===
verify if this is correct
In Manhattan WMS, once **wave picking is completed**, inventory is usually sitting in a tote, carton, or pallet at a packing station. The picker is done. Now the **packer** takes over.

The packer's job is very different from the picker's:

* Verify picked items
* Handle shortages/exceptions
* Select carton
* Pack items
* Generate shipping labels
* Close carton/LPN
* Move shipment to staging

---

# Before Packer Starts

System already has:

```text
Sales Order
   ↓
Wave Released
   ↓
Allocation
   ↓
Picking Completed
   ↓
Inventory moved to Packing Station
```

Order status may be something like:

```text
Ready for Packing
```

or

```text
Packed Pending
```

depending on configuration.

---

# What Packer Sees

RF Menu:

```text
Outbound
   → Packing
```

or on a workstation:

```text
Pack Workbench
```

Many Manhattan sites use a PC workstation with barcode scanner because packing involves labels, dimensions, weight, etc.

---

# Step 1: Scan Tote / Carton / Pick LPN

Packer receives:

```text
Tote T000123
```

or

```text
Carton C000456
```

RF displays:

```text
Scan Pick Container
```

Packer scans:

```text
T000123
```

System retrieves:

```text
Order SO10045
```

and displays:

```text
Order: SO10045

Expected:
2 × Shirt
1 × Jacket
```

---

# Step 2: Verify Items

RF asks:

```text
Scan Item
```

Packer scans:

```text
ITEM1001
```

RF:

```text
Expected Qty = 2

Enter Packed Qty
```

Packer enters:

```text
2
```

Then scans next item.

```text
ITEM2001
Qty = 1
```

---

# What Manhattan Validates

System checks:

* Correct SKU
* Correct quantity
* Correct order
* Correct inventory ownership
* Lot/Serial if applicable

If wrong item scanned:

```text
ERROR

Item not expected
```

---

Example:

# Document 7: Outbound - Shipping

=== Start ===
verify if this is correct
In Manhattan WMS, once cartons are packed and staged at the outbound doors, the **loader/shipper** takes over.

The loader's job is to:

* Verify the correct trailer is at the door
* Scan shipping LPNs as they are loaded
* Prevent "Wrong Truck" errors
* Seal the trailer
* Close the load/manifest

---

# Before Loader Starts

System already has:

```text
Packing Completed
   ↓
Cartons Staged at Door
   ↓
Load / Manifest Created
   ↓
Trailer Assigned to Door
```

Order status may be something like:

```text
Staged
```

or

```text
Ready to Load
```

---

# What Loader Sees

RF Menu:

```text
Outbound
   → Shipping
   → Load Trailer
```

---

# Step 1: Scan Door & Trailer

Loader receives:

```text
Trailer TR-889
```

RF displays:

```text
Scan Dock Door
```

Loader scans:

```text
DOOR-05
```

RF displays:

```text
Scan Trailer ID
```

Loader scans:

```text
TR-889
```

---

# Step 2: Scan Shipping LPN

As cartons are placed on the truck:

RF asks:

```text
Scan Carton LPN
```

Loader scans:

```text
SHP000567
```

System validates:

```text
Accepted
```

---

# What Manhattan Validates

System checks:

* Scanned LPN belongs to the Load/Manifest assigned to this specific Trailer/Door
* LPN is in `PACKED` or `STAGED` status
* LPN has not already been loaded on another trailer

If wrong carton scanned:

```text
ALARM!

WRONG TRUCK
LPN belongs to DOOR-02
```

---

# Step 3: Exception Handling

If a carton is damaged during loading:

RF allows:

```text
Damage LPN
SHP000567
```

System removes it from the manifest and triggers a repack task.

---

# Step 4: Close Trailer & Seal

Once truck is full:

RF displays:

```text
Load Complete?
Y/N
```

Loader presses `Y`.

RF asks:

```text
Enter Seal Number
```

Loader enters physical bolt seal:

```text
SL-993827
```

System updates:

```text
Trailer Closed
```

---

# Manhattan Transactions Created

Behind the scenes:

```text
Load Confirmation (load_dtl)
Trailer Status Update (trlr table)
LPN Status Update (lpn table)
Order Status Update (ord_hdr table)
Manifest / Bill of Lading Finalization
```

```text
Staged (Door)
        ↓

Scan & Load
        ↓

LOADED (Trailer)
        ↓

Trailer Sealed
        ↓

SHIPPED
```

So from the warehouse operator's perspective, the shipping flow is essentially:

```text
Scan Door
    ↓
Scan Trailer
    ↓
Scan Cartons (Load)
    ↓
Handle Wrong Truck Alarms
    ↓
Close Trailer
    ↓
Enter Seal Number
```

After this, the inventory leaves the four walls of the warehouse, and the Manhattan WMS lifecycle for that order is **Complete**.
